# Forge

> AI-оркестратор разработки, позволяющий масштабировать процесс создания программного обеспечения без потери архитектурной целостности.

## О проекте

Forge исследует подход к организации AI-first разработки, при котором инженерный процесс разделяется между специализированными агентами.

В отличие от классических AI-ассистентов, агент в Forge — это **роль**, а не конкретная языковая модель. Один и тот же агент может использовать GPT, Claude, Gemini или локальную LLM. Его поведение определяется инженерными правилами проекта, а не возможностями выбранной модели.

Главная задача Forge — сохранить скорость разработки без потери качества и архитектурной целостности.

## Проблема

По мере увеличения количества AI-генерируемого кода появляются типичные проблемы:

- нарушение архитектурных соглашений;
- дублирование решений;
- потеря архитектурного контекста;
- нестабильное качество кода;
- сложность масштабирования процесса.

Forge решает эти проблемы за счет оркестрации специализированных инженерных агентов.

## Архитектура

Каждая задача проходит одинаковый конвейер обработки.

```text
Запрос
   │
   ▼
Product Agent
   │
   ▼
Architecture Agent
   │
   ▼
Coding Agent
   │
   ▼
Review Agent
   │
   ▼
Testing Agent
   │
   ▼
Release Agent
```

Перед выполнением задачи каждый агент получает одинаковый контекст:

- Constitution
- Architecture Memory
- Current Task
- Previous Decisions

## Агенты

| Агент | Ответственность |
|--------|-----------------|
| Product | Анализ требований |
| Architecture | Архитектурное решение |
| Coding | Генерация реализации |
| Review | Проверка качества |
| Testing | Генерация тестов |
| Release | Подготовка релиза |

## Режим демонстрации

Запуск обрабатывает встроенную демонстрационную задачу, создает только
локальные артефакты и не изменяет код целевого приложения.

```text
Задача: «Добавить экспорт отчета в PDF»

Требования:
- создать экспорт PDF;
- обработать ошибки генерации.

Критерии приемки:
- PDF успешно создается;
- ошибки корректно обрабатываются.
```

Для более полного демонстрационного прогона можно использовать задачу:

```text
Задача: «Добавить асинхронное формирование и доставку аналитического отчета»

Описание:
Пользователь выбирает период и формат отчета, запускает его формирование
в фоновом режиме и получает уведомление о готовности с временной ссылкой
на скачивание.

Требования:
- создать фоновую задачу формирования отчета;
- отображать статусы «в очереди», «выполняется», «готово» и «ошибка»;
- отправлять уведомление после успешного формирования;
- повторять временные ошибки доставки не более трех раз;
- хранить результат не дольше 24 часов.

Ограничения:
- не менять существующий публичный API отчетов;
- не блокировать пользовательский запрос на время формирования;
- не включать персональные данные в текст уведомления.

Критерии приемки:
- пользователь получает идентификатор фоновой задачи сразу после запуска;
- статус задачи доступен до завершения обработки;
- готовый отчет доступен по временной ссылке;
- при ошибке доставки выполняются повторные попытки и фиксируется итоговый статус;
- результаты удаляются после окончания срока хранения.
```

## Запуск demo pipeline

Требуется Python 3.12 или новее. В корне репозитория выполните:

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
PYTHONPATH=src python src/main.py
```

Команда запускает встроенную задачу «Добавить экспорт отчета в PDF» и
выводит итоговый отчёт аналитики в консоль. После успешного прогона
появятся локальные журналы в `logs/` и архитектурное решение в
`memory/decisions/`.

## Принципы

- Архитектура важнее скорости.
- Один агент — одна ответственность.
- Все решения документируются.
- AI не изменяет архитектуру самостоятельно.
- Контекст проекта важнее контекста отдельной задачи.
- Человек управляет процессом, AI ускоряет его.
