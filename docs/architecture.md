# Архитектура Forge

## Назначение

Forge — это оркестратор инженерных агентов, предназначенный для организации процесса AI-first разработки.

В Forge агент — это **инженерная роль**, а не конкретная языковая модель. Каждый агент выполняет одну задачу в рамках общего процесса разработки, используя единый архитектурный контекст и инженерные правила проекта.

Главная цель системы — обеспечить масштабируемый процесс разработки, при котором рост количества AI-генерируемого кода не приводит к деградации архитектуры и качества продукта.

---

# Архитектурные принципы

Forge строится на следующих принципах:

- один агент — одна ответственность;
- единый архитектурный контекст для всех агентов;
- инженерные правила обязательны для всех участников процесса;
- взаимодействие только через формализованные контракты;
- каждое архитектурное решение документируется;
- человек остается владельцем архитектуры.

# Общая схема

```text
                      ┌──────────────────┐
                      │       Task       │
                      └────────┬─────────┘
                               │
                               ▼
                    ┌────────────────────┐
                    │    Orchestrator    │
                    └────────┬───────────┘
                             │
                             ▼
                  Product Agent
                             │
                             ▼
               Architecture Agent
                             │
                             ▼
                  Coding Agent
                             │
                             ▼
                  Review Agent
                             │
                             ▼
                  Testing Agent
                             │
                             ▼
                  Release Agent
                             │
                             ▼
                          Result
```

Оркестратор управляет последовательностью выполнения, но не принимает инженерных решений.

---

# Основные компоненты

## Orchestrator

Центральный компонент системы.

Отвечает за:

- запуск обработки задачи;
- передачу контекста между агентами;
- контроль последовательности выполнения;
- обработку ошибок;
- сохранение результатов каждого этапа.

---

## Engineering Agent

Каждый инженерный агент представляет собой независимого исполнителя одной инженерной роли.

Любой агент состоит из четырех частей.

```text
Agent
├── Prompt
├── Context
├── Provider Adapter
└── Output Validator
```

### Prompt

Определяет обязанности, ограничения и ожидаемый результат работы агента.

### Context

Содержит всю информацию, необходимую для выполнения задачи.

### Provider Adapter

Абстракция над конкретной языковой моделью.

Позволяет использовать различных поставщиков LLM без изменения логики системы.

Например:

- OpenAI
- Anthropic
- Google Gemini
- локальные модели

### Output Validator

Проверяет корректность результата и его соответствие ожидаемому контракту.

---

# Общий контекст

Перед началом выполнения каждый агент получает одинаковый контекст.

```text
Context
├── Constitution
├── Architecture Memory
├── Current Task
├── Previous Decisions
└── Project Metadata
```

Это гарантирует, что все участники процесса принимают решения, основываясь на одинаковой информации.

---

# Constitution

Constitution — главный источник инженерных правил проекта.

Документ определяет ограничения, обязательные для всех агентов.

Примеры правил:

- направление зависимостей;
- изоляция модулей;
- требования к тестируемости;
- правила именования;
- ограничения на изменение публичных интерфейсов.

Ни один агент не имеет права игнорировать Constitution.

---

# Architecture Memory

Architecture Memory хранит знания проекта между выполнением задач.

В памяти сохраняются:

- архитектурные решения;
- описание компонентов системы;
- терминология проекта;
- история изменений;
- ранее принятые соглашения.

Новые записи появляются только после успешного завершения обработки задачи.

---

# Pipeline обработки задачи

Каждая задача проходит одинаковый набор этапов.

```text
Task
  │
  ▼
Product Agent
  │
  ▼
Architecture Agent
  │
  ▼
Coding Agent
  │
  ▼
Review Agent
  │
  ▼
Testing Agent
  │
  ▼
Release Agent
```

Если агент возвращает ошибку или нарушение архитектурных правил, выполнение конвейера останавливается.

Оркестратор возвращает результат последнего успешного этапа и описание причины остановки.

---

# Контракты взаимодействия

Агенты не взаимодействуют напрямую.

Каждый агент:

- получает входной контракт;
- возвращает выходной контракт;
- не имеет информации о внутренней реализации других агентов.

Такой подход позволяет заменять отдельные компоненты системы без изменения остальной архитектуры.

---

# Расширяемость

Архитектура допускает добавление новых инженерных агентов без изменения существующего процесса.

Например:

- Security Agent
- Performance Agent
- Documentation Agent
- Database Agent
- UX Agent

Оркестратор определяет порядок их выполнения на основании конфигурации процесса.

---

# Ограничения MVP

Первая версия Forge сознательно ограничена.

Не реализуются:

- параллельное выполнение агентов;
- распределенная обработка задач;
- автоматическое разрешение конфликтов;
- интеграция с CI/CD;
- собственные языковые модели;
- автоматический выбор поставщика LLM.

Главная задача MVP — продемонстрировать архитектуру оркестрации инженерных агентов и процесс AI-first разработки.
